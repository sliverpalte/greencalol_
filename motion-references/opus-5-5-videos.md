# Opus 5.5 모션 영상 프롬프트 정리

코드로 만든 모션 영상 475개 중 릴스·뉴스카드에 쓸 만한 것만 골라 기법 단위로 정리했다.
영상을 만들 때 "어떤 연출을 어떻게 지시하면 잘 나오는지" 참고하는 용도다.

- 출처: https://github.com/yihui-dev/awesome-opus5-5-videos (MIT, 2026-09-30 기준). 원본 영상은 각 항목의 Skillry·X 링크에서 본다.
- 프롬프트 원문은 각 작성자의 것이다. 여기서는 기법만 요약하고, 원문 문구·브랜드·팔레트를 그대로 가져다 쓰지 않는다 (CLAUDE.md 공통 규칙).
- 효과 이름은 `rules/motion/camera-guide.md` 번호(01~23)로 적는다. 수치·구현은 `rules/motion/motion-system.md`가 우선한다.

## 1. 잘 나온 프롬프트들의 공통 패턴

좋은 결과를 낸 프롬프트는 거의 다음 구조를 따른다. 우리 릴스 지시서도 이 순서로 쓴다.

| 블록 | 내용 | 우리 쪽 대응 |
|---|---|---|
| inputs | 시작 전에 받아야 할 것(문구, 상태 목록, 강조색, 음악)을 먼저 묻게 함 | reels.md 0~1단계 |
| direction | 분위기 한 줄 + **금지 목록** (파티클, 글로우, 통통 튀는 이징, 템플릿 느낌 등) | motion-system 4장 "피해야 할 흔한 결과물" |
| structure | BPM과 마디 수, 마디마다 일어날 일 한 줄씩 | 장면 레시피 A~E |
| build | 시간→화면 순수 함수, 스프링 공식, 렌더 방법 | Remotion `useCurrentFrame()` |
| gotchas | 실제로 깨졌던 것 | 아래 3장 |
| start | "코드 쓰기 전에 박자표·스토리보드부터 보여줘" | reels.md "단계마다 확인받기" |

### 반복해서 나오는 기술 규칙

1. **시간의 순수 함수.** 모든 화면 값은 `seek(t)` 하나로 계산하고 CSS transition·타이머·프레임 간 상태를 쓰지 않는다. Remotion에서는 `useCurrentFrame()` 기준 계산이 같은 원리다.
2. **스프링은 닫힌 식으로.** 목표가 여러 번 바뀌는 값은 "바뀔 때마다 스프링 하나씩 더한 합"으로 만든다. 그래야 어느 프레임을 렌더해도 같은 결과가 나온다. Remotion의 `spring({frame: frame - 시작프레임})`을 구간마다 더하면 된다.
3. **박자표(120 BPM).** 거의 모든 프롬프트가 120 BPM을 쓴다. 30fps 기준 1박 = 15프레임, 1마디(4박) = 60프레임, 16분음표 = 3.75프레임(→ 4프레임). 컷은 마디 첫 박에, UI 변화는 박에 둔다.
4. **스태거 = 16분음표.** 글자별 등장 간격을 박자에 묶는다(120 BPM이면 4프레임). motion-system의 22번 간격표 범위 안이다.
5. **렌더 전 콘택트 시트.** 박마다(또는 20장 이상) 스틸을 뽑아 한 장에 깔고, 글자 겹침·잘림·답답함을 고친 뒤에 전체 렌더한다.
6. **서브프레임 모션 블러.** 한 프레임을 3~4개 시점으로 렌더해 섞는다(ffmpeg `tmix`). 우리는 23번 규칙대로 빠른 구간에만 `@remotion/motion-blur`를 쓴다.
7. **효과음은 파형 정점 기준.** 파일 시작점이 아니라 소리의 가장 큰 지점이 이벤트 프레임에 오게 놓는다. 음악 아래로 작게, 최종 -14 LUFS.
8. **루프.** 마지막 프레임 = 첫 프레임(위치·투명도·커서 속도까지). 피드에서 반복 재생될 때 이음새가 안 보인다.
9. **사실만.** 화면의 숫자·라벨은 실제 자료에서만 가져오고, 지어낸 %·배수·고객 이름을 넣지 않는다.

## 3. 레퍼런스들에 나온 함정 (검수 때 확인)

- `preserve-3d` 요소에 opacity·filter를 주면 평평해져 앞뒤 면이 다 보인다 → 감싼 부모에 준다.
- 카메라가 확대하는 요소에 `will-change`를 걸면 글자가 흐려진다.
- 변형되는 컨테이너 안의 글자는 들어오고 나가는 타이밍을 따로 줘야 겹치지 않는다.
- 루프는 마지막 프레임의 커서 위치·속도까지 첫 프레임과 같아야 이음새가 안 튄다.
- 효과음은 파일 시작이 아니라 정점을 이벤트 프레임에 맞춘다.
- 자막은 실제 폰트로 측정해 안전 영역에 맞춘다 (`measuring-text`). 우리 데드존: 상단 270, 하단 480, 좌우 65px.

## 4. 우리 릴스용 지시서 틀

위 패턴을 rules/reels.md 규격에 맞춰 합친 틀. `{ }` 부분만 채워서 쓴다.

```text
<inputs>
먼저 물어볼 것: 핵심 문구 {한 줄}, 보여줄 장면 {3~5개}, 강조색 {1개},
사용할 사진·영상 {사용자 제공분만}, 음악 {사용 허가 확인된 것, 없으면 무음}.
</inputs>

<direction>
분위기: {다크 테크 | 에디토리얼 | 소프트 미니멀 | 브루탈} 중 하나 (motion-system 4장).
한 장면에 아이디어 하나, 여백 넉넉히, 강조색 1개, 한글 폰트 {Pretendard} 최대 2종.
금지: 파티클 폭발, 글로우, 무지개 그라데이션, 카메라 흔들림, 통통 튀는 이징, 장면마다 다른 전환.
</direction>

<structure>
1080×1920, 30fps, {15}초. 120 BPM → 1박 15프레임, 1마디 60프레임.
마디 1 (0~2초): 훅 문구가 박마다 단어 단위로 등장 (22 스태거 4프레임 + 19 이즈 아웃).
마디 2~{n}: 마디마다 동작 하나. {장면별 한 줄씩}
마지막 2~3초: 계정 이름 + 저장·팔로우 문구, 움직임 정지.
전환은 한 가지만 (09 휩 팬 11프레임 + 그 구간만 23 모션 블러), 컷은 마디 첫 박에.
</structure>

<build>
Remotion. 모든 값은 useCurrentFrame() 기준, CSS transition·타이머 금지.
목표가 여러 번 바뀌는 값은 구간별 spring()의 합으로.
글자는 데드존(상단 270, 하단 480, 좌우 65px, 우측 버튼 영역) 밖에만, measuring-text로 측정.
화면 숫자·라벨은 받은 자료에서만.
</build>

<check>
코드 전에 박자표(마디별 장면·프레임 번호)를 먼저 보여줄 것.
렌더 전에 박마다 스틸을 뽑아 콘택트 시트로 확인하고, 겹침·잘림·답답함을 고친 뒤 렌더.
</check>
```
