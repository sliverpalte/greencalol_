# 제작 기준 보강 — OpenMontage 분석 정리

[OpenMontage](https://github.com/calesthio/OpenMontage)(AGPL-3.0, Remotion 기반 AI 영상 제작 파이프라인)의 스킬 문서와 Remotion 컴포넌트를 읽고, 우리 릴스·카드뉴스 작업에 빠져 있던 기준만 골라 정리한 문서다.
코드는 가져오지 않았다(라이선스). 수치와 방법만 우리 규칙에 맞게 다시 썼다.

우선순위: 사용자 요청 > `camera-guide.md` > `motion-system.md` > `reels.md`·`news-card.md` > 이 문서.
특히 **데드존은 `reels.md` 값(상단 270·하단 480·좌우 65px)이 OpenMontage 값보다 엄격하므로 그대로 쓴다.** 이징 곡선도 `motion-system.md` 토큰을 쓰고, 이 문서의 시간 값만 참고한다.

## 1. 길이별 구성

첫 프레임부터 움직임과 글자가 있어야 한다. 로고·빈 화면·인사로 시작하지 않는다. 화면 변화는 1~3초마다, 같은 화면이 3초를 넘게 멈춰 있지 않게 한다 (단, 글을 읽는 정지 시간은 2장 기준을 지킨다).

**15초 (기본)**
```
0~1초    훅: 핵심 문구 첫 프레임 등장 (motion-system 레시피 A)
1~3초    맥락 한 문장
3~12초   본론: 팁·사실·제품 (말보다 화면으로)
12~15초  마무리: 결과 + 계정명·행동 유도 (레시피 E)
```

**30초**
```
0~1초    훅: 질문 또는 패턴 깨기
1~5초    문제: 왜 중요한지
5~22초   해결: 2~3초마다 화면 변화
22~27초  결과
27~30초  마무리·행동 유도
```

**60초**
```
0~2초    훅: 완성된 결과부터 보여주기
2~8초    "N단계로 알려드림"
8~45초   단계 3~5개, 단계당 약 8초
45~55초  전후 비교 또는 최종 결과
55~60초  마무리 + 첫 장면으로 이어지는 루프
```

훅 유형: 결과 먼저 / 질문 / 상식 뒤집기 / 굵은 문구 / 예상 못 한 화면. 문구 자체는 `viral-hook-writer`로 쓴다.

## 2. 글자 노출 시간·자막

### 노출 시간
- 글자 등장 애니메이션이 끝난 뒤부터 읽는 시간을 센다.
- 한글 기준 초당 12자 이하로 읽히게 둔다 (넷플릭스 한국어 자막 가이드의 성인용 기준). 예: 24자 문구 → 정지 2초 이상.
- 이 값과 `reels.md`의 "최소 2초", `motion-system.md`의 "한 줄 1.5초 이상" 중 **가장 긴 값**을 쓴다.
- 제목·숫자 카드: 3초 안팎. 차트: 다 그려진 뒤 3초 이상 정지.

### 자막(말소리 받아쓰기)
| 항목 | 값 |
|---|---|
| 한 줄 글자 수 | 한글 12자 이내 (CLAUDE.md 영상 제작 규칙) |
| 줄 수 | 최대 2줄 |
| 한 덩어리 노출 | 최소 1초, 최대 6초 |
| 덩어리 사이 간격 | 2프레임 |
| 음성과 어긋남 허용 | 3프레임 이내 |
| 크기 | 72px 이상 (CLAUDE.md "자막 크게") |
| 배경 | 검정 70~80% 박스, 또는 흰 글자 + 어두운 외곽선 2~4px |

### 단어 강조 자막 구조 (`remotion-captions`로 만들 때)
- 단어(한글은 어절) 타이밍 목록을 "페이지" 단위로 묶어 `Sequence` 하나씩 띄운다. 페이지 = 3~6어절, 문장 끝에서는 강제로 끊는다.
- 지금 말하는 어절만 강조색, 지난 어절은 기본색, 아직 안 나온 어절은 기본색 60% 투명도.
- 어절은 `display: inline-block; white-space: nowrap`으로 감싸 어절 중간에서 줄이 바뀌지 않게 한다.
- 페이지 등장은 아래 20px → 0 + 투명도, `springSettle`.
- **위치는 하단 480px 데드존 위에 둔다.** 화면 아래에 바짝 붙이는 일반적인 자막 위치는 우리 규칙에서 금지.

## 3. 오디오 레벨·효과음 타이밍

### 최종 믹스
| 항목 | 값 |
|---|---|
| 전체 음량 | -14 LUFS (인스타 릴스 기준) |
| 최고점 | -1 dBTP 이하 |
| 샘플레이트 | 48kHz |

### 요소별 레벨
| 요소 | 최고점 | 메모 |
|---|---|---|
| 내레이션·말소리 | -12 ~ -6 dB | 기준 |
| 배경음악 (말이 있을 때) | 말보다 18~20dB 낮게 | 말 구간에서만 덕킹 |
| 배경음악 (말이 없을 때) | -14 ~ -10 dB | 음악 중심 릴스 |
| 효과음 | -18 ~ -12 dB | 말보다 6dB 이상 낮게 |
| 임팩트(핵심 숫자 등장) | -12 ~ -6 dB | 영상당 1~2번 |

음악 볼륨을 정했다고 생각한 지점에서 4dB 더 내리면 대부분 맞다. 휴대폰 스피커로 들어 보고 말이 묻히면 음악을 더 내린다.

### 효과음 종류·길이
| 종류 | 쓰는 곳 | 길이 |
|---|---|---|
| 휙(swoosh) | 장면 전환, 휩 팬(09) | 0.4~0.5초 |
| 팝 | 글자·배지 팝인 | 0.2초 이하 |
| 클릭·탭 | 커서 버튼 클릭 | 0.1초 이하 |
| 라이저 | 리빌 직전 고조 | 1~3초 |
| 임팩트 | 핵심 숫자·제품 등장 | 0.3초 이하 |

### 타이밍
- 휙 효과음은 화면 변화보다 10~20ms 먼저 시작한다. 30fps에서는 **효과음을 1프레임 앞에 둔다.**
- 휙 소리의 가장 큰 지점이 화면 변화가 가장 큰 프레임(전환 중간)에 오게 맞춘다.
- 효과음을 여러 개 겹치면 음역이 다른 것(낮은 휙 + 높은 팝)으로 고른다.

### 음악 BPM 고르기
| 분위기 | BPM |
|---|---|
| 차분한 정보형 | 90~110 |
| 경쾌한 소개·프로모션 | 110~130 |
| 빠른 할인·신제품 | 120~140 |

말소리가 있으면 가사 없는 곡을 쓴다. 30fps에서 한 박 프레임 수 = 1800 ÷ BPM (예: 120BPM → 15프레임).

## 4. 렌더링 설정 (`remotion-render`)

- H.264, 비트레이트 8~15Mbps. 5Mbps보다 낮으면 인스타가 화질을 더 깎는다.
- 기본 명령 예: `npx remotion render <Comp> out.mp4 --codec h264 --video-bitrate 12M --audio-bitrate 192k`
- 결과 파일이 크면(모바일 업로드 한계를 고려해 70MB 이상) 비트레이트를 8M까지 낮춘다.
- 렌더 후 전체 음량을 확인하고(`ffmpeg -af loudnorm=print_format=summary`), -14 LUFS에서 크게 벗어나면 음악·효과음 볼륨을 고쳐 다시 렌더한다.

## 5. 데이터 장면 (motion-system 레시피 C 보강)

### 형식 고르기
```
데이터 1~2개         → 숫자 카드 (차트 쓰지 않음)
항목끼리 크기 비교    → 막대 (항목 이름이 길면 가로 막대)
시간에 따른 변화      → 꺾은선
전체 중 비율         → 도넛 (최대 5조각, 작은 건 "기타")
핵심 수치 여러 개     → 숫자 카드 2×2 격자 (최대 4개, 9:16 기준)
전후 비교            → 비교 카드 또는 나란한 막대 + 증감 표시
```
릴스·카드뉴스 한 화면의 항목 수: 막대 5개 이하, 꺾은선 점 7개 이하.

### 움직임 패턴
| 패턴 | 순서 | 쓰는 때 |
|---|---|---|
| 차오르기 (기본) | 빈 축 → 0.3초 뒤 막대 스태거(3~4프레임) → 다 차면 정지 3초 이상 | 대부분 |
| 하나씩 강조 | 전체를 30% 투명도로 보여주고 말하는 항목만 진하게 + 살짝 확대 | 내레이션이 항목을 짚을 때 |
| 전후 비교 | 이전 값 2초 보여줌 → 1~2초 동안 이후 값으로 변화 → 증감 라벨 등장 | 가격 인하, 성능 향상 |

| 요소 | 움직이는 시간 | 정지 시간 |
|---|---|---|
| 차트 전체 | 2~4초 | 3초 이상 |
| 숫자 카운트업 | 1.5~2초 | 2~3초 |
| 라벨 | 0.2~0.3초 | 끝까지 유지 |

라벨 규칙: 값은 막대 위(가로 막대는 오른쪽), 단위(원·%·GB)는 반드시 표시, 출처가 있으면 아래에 작게.

## 6. 장면 유형 카탈로그

장면마다 새로 짜지 않고, 아래 유형을 Remotion 컴포넌트 하나씩으로 만들어 props만 바꿔 재사용한다. 만든 컴포넌트는 브랜드 템플릿 폴더에 저장하고 이 표에 "있음"으로 표시한다.

| 유형 | 필수 입력 | 쓰는 곳 | 레시피 |
|---|---|---|---|
| 문구 카드 | 문구 | 한 화면 한 덩어리 메시지 | A |
| 제목 카드 | 제목, 부제 | 훅, 마무리 | A, E |
| 숫자 카드 | 숫자, 설명 | 가격·수치 하나 강조 | A, C |
| 비교 카드 | 왼쪽 라벨·값, 오른쪽 라벨·값 | 전후, 경쟁 비교 | C |
| 막대·꺾은선·도넛 | 데이터 목록 | 5장 참고 | C |
| 숫자 격자 | 수치 2~4개 | 스펙 요약 | C |
| 진행 막대 | 진행률 | 단계, 할인율 | C |
| 강조 박스 | 제목, 항목 | 주의·팁 | — |
| 제품 리빌 | 누끼 PNG | 제품 등장 | B |
| 마무리 태그 | 계정명, 행동 유도 문구 | 마지막 2~3초 | E |
| 단어 강조 자막 | 어절 타이밍 목록 | 말소리가 있는 영상 | 2장 |

규칙: 모든 장면 컴포넌트는 `useCurrentFrame()` 기준으로만 움직이고 CSS transition은 쓰지 않는다. 숫자 카드의 숫자는 강조색·가장 큰 크기, 설명은 숫자보다 8프레임 늦게 등장.

## 7. 브랜드 플레이북 항목 (`brands/<브랜드>/DESIGN.md`)

브랜드 규칙을 정리할 때 색·글꼴 외에 아래 항목도 채워 둔다. 다음 영상에서 그대로 쓸 수 있게 한다.

```
분위기: (motion-system 4장 유형 중 하나) / 속도: 느림·보통·빠름

  장면 최소·최대 길이, 문구 카드 정지 시간, 숫자 카드 정지 시간, 전환 길이
```

## 8. 레퍼런스 분석 5요소 (`reel-analyzer` 결과 정리 형식)

레퍼런스 영상은 컷(또는 컷 묶음)마다 아래 다섯 항목을 모두 적는다. 해당 없는 항목은 지우지 말고 "없음"이라고 쓴다. 항목을 말없이 빼먹는 것이 가장 흔한 실수다.

| 항목 | 적을 것 |
|---|---|
| 대상 | 무엇이 몇 개, 특징. 컷 사이 변화: 등장 / 사라짐 / 바뀜 / 번갈아 |
| 대상 움직임 | 시간 순서대로의 동작 |
| 장면 | **글자·그래픽 오버레이는 따로 적는다** + 시점(위에서, 손에 든, 고정 등) + 배경 + 시간대 |
| 화면 구도 | 화면 크기(클로즈업~풀샷), 대상 위치, 앞·뒤 레이어 사용, 컷 안에서의 변화 |
| 카메라 | 재생 속도(슬로우·타임랩스), 초점 변화, 흔들림, 움직임 → **camera-guide 번호(01~23)로 적는다** |

추가로 각 컷이 실제 영상인지 / 사진을 움직인 것인지 / 정지 화면인지 구분한다. 이 구분에 따라 촬영(`b-roll-shot-list`)이 필요한지, 사진+Remotion으로 되는지가 갈린다. 추측하지 말고 프레임을 뽑아 확인한다.

마지막에 "잘 되는 이유" 2~3가지(훅 방식, 템포, 전환, 문구 스타일)를 적어 사용자에게 보여준다.

## 9. 연출 문구 규칙

장면 설명·대본 지시문에 감정 단어 대신 화면에서 보이는 원인을 적는다. 그래야 만들 때 해석이 갈리지 않는다.

| 쓰지 않음 | 이렇게 |
|---|---|
| 임팩트 있게 등장 | 4프레임 스냅 줌(10) + 임팩트 효과음, 첫 킥에 맞춤 |
| 고급스러운 느낌 | 거의 검정 배경, 제품 뒤 은은한 빛 번짐, 느린 달리 인(06) 2초 |
| 신나는 분위기 | 128BPM, 박자마다 컷, 단어 팝인 2프레임 간격 |
| 극적인 반전 | 0.5초 무음 + 화면 정지 뒤 펀치 인(11) |

## 10. 검수 기록

`motion-system.md` 6장 검수를 마친 뒤, 사용자에게 보여주기 전에 문제를 아래 형식으로 정리한다.

- **심각**: 고치지 않으면 내보낼 수 없음 (데드존 침범, 글자 넘침, 싱크 3프레임 이상 어긋남, 오탈자). **어떻게 고칠지까지 적는다.** 고칠 방법을 못 대면 "확인 필요"로 둔다.
- **제안**: 고치면 확실히 나아짐. 바꿀 내용을 적는다.
- **사소**: 다듬기.

문제 하나를 찾으면 같은 종류가 다른 장면에도 있는지 끝까지 훑는다. 심각 항목이 있으면 고치고 다시 검수한다. 두 번 고쳐도 남으면 남은 문제를 사용자에게 알리고 넘긴다.

적는 예: "3번 장면 문구 28자인데 정지 1.2초 → 초당 12자 기준 2.4초 필요. 장면을 1.2초 늘리거나 문구를 14자로 줄임."
