# 카메라 움직임 및 모션그래픽 작업 지침

## 이 문서의 범위

사용자가 제공한 카메라 움직임·모션 타이밍 카드 23장(IMG_6139.png~IMG_6161.png)을 정리한 작업 참고 문서다. 카드에는 @juoouse 표기가 있다. 제공된 01~23번 카드 전체를 반영했다. 노션 페이지 자체는 접근하지 못했으므로, 카드 외의 노션 본문이나 첨부 자료까지 확인한 것으로 취급하지 않는다.

아래 '원문 내용 정리'는 제공된 카드에서 확인한 내용이다. '구현 지침'과 '검수 기준'은 이를 코드로 구현하기 위해 추가한 지침이며 원문 인용이 아니다.

## 역할과 기본 원칙

사용자의 자연어 요청을 카메라 움직임 또는 2D 모션그래픽으로 해석하고 구현한다. 기존 프로젝트의 기술과 구조를 먼저 확인한다. 특정 영상 도구나 라이브러리가 설치되어 있다고 가정하지 않는다.

- 카메라가 회전하는지, 이동하는지, 렌즈 화각이 바뀌는지 먼저 구분한다.
- 정지 이미지 한 장의 위치·크기 변화는 실제 3D 카메라 움직임과 구분한다.
- 요청에 방향, 이동량 또는 각도, 시작 시점, 지속시간, 대상, 종료 상태를 반영한다.
- 로고·제품 라벨·자막의 철자와 가독성을 보존한다. 제품 비율을 임의로 늘이거나 줄이지 않는다.
- 확인하지 않은 파일, 도구 실행, 렌더 결과를 완료했다고 말하지 않는다.

### 원문의 프레임 표기

- 휩 팬 카드: 30fps 기준 11프레임, 약 0.36초. 요청 예시는 0.4초 이내.
- 스냅 줌 카드: 30fps 기준 4프레임, 약 0.13초.
- 이 수치는 카드의 예시다. 모든 영상에 고정해서 적용하지 않는다.

## 구현 지침 — 원문을 바탕으로 추가

### 팬·틸트와 트랙·페데스탈을 구분한다

실제 팬과 틸트는 카메라의 회전이다. 2D에서 큰 장면 레이어를 좌우 또는 위아래로 이동해 비슷한 인상을 만들 수 있지만, 이것은 화면 이동으로 흉내 낸 효과다. 실제 회전과 완전히 같은 투영 결과라고 설명하지 않는다.

트랙과 페데스탈은 카메라 위치가 변한다. 깊이 표현이 필요하면 전경·중경·배경을 분리하고 가까운 레이어를 더 많이 이동시킨다. 모든 레이어를 같은 양으로 옮겼다면 깊이 차이는 구현되지 않은 것이다.

카메라가 오른쪽으로 움직이는 요청과 화면 속 물체가 오른쪽으로 움직이는 요청을 구분한다. 일반적으로 정지한 장면을 카메라가 오른쪽으로 바라보거나 이동하면 장면은 화면에서 왼쪽으로 흐른다. '오른쪽으로 팬'을 무조건 요소의 오른쪽 이동으로 번역하지 않는다.

### 롤

2D 구현은 장면 전체를 회전시킨다. 제목이나 자막까지 기울일지는 요청에 따라 별도로 정한다. 회전으로 모서리에 빈 공간이 생기면 충분한 여유 이미지 또는 확대를 사용한다. 기울기 방향이 지정되지 않았으면 사용한 방향을 설명한다.

### 달리와 줌

달리는 카메라의 앞뒤 이동이다. 3D에서는 카메라 위치를 바꾸고, 2D에서는 깊이가 다른 레이어를 서로 다른 비율로 확대·이동해 근사한다. 한 장의 이미지를 일괄 확대하는 방식은 깊이 변화가 있는 달리로 취급하지 않는다.

줌은 렌즈 화각의 변화다. 2D에서는 전체 장면을 일정한 기준점으로 확대해 근사할 수 있다. 제목이나 제품을 확대할 때 기준점을 해당 대상에 두어 화면 밖으로 밀리지 않게 한다.

카드의 '렌즈만 당겨요'는 간단한 설명이다. 실제 구현에서는 카메라 위치를 유지하면서 초점거리 또는 화각을 바꾸는 것으로 해석한다.

### 오빗

실제 오빗에는 카메라의 곡선 이동과 대상을 향하는 시선 유지가 필요하다. 3D 모델이나 여러 방향의 이미지가 있으면 이를 사용한다. 제품 정면 사진 한 장으로 보이지 않는 옆면과 뒷면을 정확하게 만들어낼 수 있다고 가정하지 않는다.

정지 이미지 한 장만 있을 때는 레이어 이동으로 오빗 분위기를 근사할 수 있다. 결과가 2D 근사임을 밝히고, 포장 구조나 라벨을 임의로 생성하지 않는다. 정확한 180도 회전이 요구되면 필요한 추가 자료를 구체적으로 요청한다.

### 휩 팬

첫 장면을 빠르게 밀고 새 장면을 같은 방향과 타이밍으로 연결한다. 전환 구간에 방향성 모션 블러를 사용할 수 있다. 종료 후에는 잔상이 사라지고 새 장면이 선명해야 한다. 블러를 오래 유지해 제품이나 글자를 읽기 어렵게 만들지 않는다.

### 스냅 줌

지정된 짧은 프레임 구간에 확대를 끝내고 대상이 선명하게 보이는 상태로 정착시킨다. 순간적인 블러나 약한 반동은 추가 선택사항이다. 별도 요청 없이 계속 흔들리게 만들지 않는다.

### 펀치 인과 스냅 줌의 차이

펀치 인은 컷 전환이다. 지정 시점 이전에는 원래 구도, 해당 시점부터는 확대 구도를 사용한다. 확대하는 중간 프레임이나 보간을 넣지 않는다. 스냅 줌은 매우 짧더라도 확대 과정이 있는 애니메이션이다.

### 달리 줌

12번 카드의 제목은 '줌 아웃 트랙 인'이며 영어 표기는 Dolly Zoom이다. 앞 카드에서 Track은 옆 이동을 뜻했지만, 여기서는 카메라의 앞으로 이동을 지시한다. 이 문맥은 달리 인과 줌 아웃의 동시 적용으로 해석한다.

3D에서는 카메라와 대상의 거리를 줄이며 화각을 넓혀 대상의 화면 크기를 유지한다. 2D 근사에서는 대상 레이어 크기를 고정하고 배경 레이어 크기·위치를 변화시킨다. 이는 실제 3D 공간 전체의 투영 변화와 동일하지 않다. 단일 이미지 전체를 축소하면 대상 크기도 변하므로 요구를 충족하지 못한다.

### 스피드 램핑

속도 변화와 위치 변화 곡선을 구분한다. 이동 경로는 유지하고 시간에 따른 진행률을 조절한다. 느림·빠름·느림을 구간으로 나누되 구간 경계에서 위치가 튀지 않게 연결한다. 카드 예시는 총 1.3초다. 기존 영상에 적용할 때는 소스의 재생 시점을 재매핑하고, 새 모션에 적용할 때는 애니메이션 진행률을 재매핑한다. 소리의 재생 속도도 바꿀지는 별도로 판단한다.

### 패럴랙스와 2.5D

패럴랙스는 깊이에 따른 상대적인 움직임이고, 2.5D는 평면 자산에 깊이 좌표를 부여하는 구성 방식이다. 같은 효과명으로 취급하지 않는다. 레이어별 이동량·깊이를 설정 가능한 값으로 두고 앞 레이어를 더 많이 이동시킨다. 잘라낸 대상 뒤쪽이 드러날 수 있으므로 배경의 빈 영역을 확인한다. 한 장의 그림만 있을 때는 임의로 분리된 레이어가 존재한다고 가정하지 않는다.

2.5D에서 평면 카드를 돌리는 것은 제품의 실제 입체 구조를 재현하는 것과 다르다. 큰 회전으로 레이어가 얇은 판처럼 보이면 회전 범위를 줄이거나 추가 자료를 사용한다.

### 랙 포커스

대상의 크기·위치를 바꾸는 대신 앞·뒤 레이어의 선명도를 반대로 변화시킨다. 3D에서는 초점 거리와 피사계 심도를 조절하고, 2D에서는 분리된 레이어의 블러로 근사한다. 전체 화면에 동일한 블러를 주면 초점 이동이 아니다. 종료 시 강조 대상은 선명해야 한다. 화면에 고정된 안내 자막이나 로고를 장면의 초점 효과에 포함할지는 구분한다.

### 퍼스펙티브 틸트

화면 평면의 기울기와 원근 투영을 함께 적용한다. 2D 화면 내 회전만으로 대신하지 않는다. 카메라의 상하 회전인 02번 틸트, 화면 내 회전인 03번 롤과 구분한다. 위쪽이 멀어지는 요청이면 실제 결과가 그 방향인지 미리보기로 확인한다. 코드의 회전 부호는 사용하는 좌표계에 따라 다를 수 있다.

### 이징·이즈 아웃·오버슈트

이징은 시간에 따른 진행률을 바꾸는 상위 개념이고 이즈 아웃은 그중 감속하며 도착하는 유형이다. 이즈 아웃은 카드나 제목의 등장에 사용할 수 있다. 계속 일정하게 흘러야 하는 배경이나 루프에는 리니어가 맞을 수 있으므로 18번 예시를 모든 모션의 절대 규칙으로 적용하지 않는다.

오버슈트는 목표값을 잠깐 넘겼다가 돌아오는 형태다. 한 번의 반동과 반복되는 바운스를 구분한다. 110%는 카드의 예시이며 사용자 요청과 프로젝트 스타일에 맞게 조절한다. 크기 변화의 기준점을 유지하고, 최종값에 정착해 계속 떨리지 않게 한다. 제품을 확대할 때는 가로·세로 비율을 함께 유지한다.

### 안티시페이션

본 동작 직전에 반대 방향의 작은 준비 동작을 넣는다. 점프라면 먼저 살짝 내려갔다가 올라간다. 오버슈트는 목표에 도착할 때의 반동이고, 안티시페이션은 출발 전의 준비이므로 구간을 구분한다. 0.15초는 원문 예시이며 실제 fps로 환산한다. 준비 구간을 기존 전체 길이 안에 넣을지, 시작을 앞당길지 판단하고 전체 길이를 임의로 늘리지 않는다.

캐릭터의 웅크림은 허용된 변형 범위에서 구현한다. 제품이나 로고에는 몸을 찌그러뜨리는 표현을 그대로 적용하지 말고 작은 위치 이동 등으로 준비 동작을 표현한다.

### 스태거

0부터 시작하는 요소 인덱스 i에 대해 시작 시점은 기본 시작 시점 + i × 간격으로 계산한다. 각 요소의 진행률은 자기 시작 시점을 기준으로 계산한다. 0.1초 간격의 카드 3장이면 시작 시점은 0초, 0.1초, 0.2초다. 이는 각 카드의 애니메이션 길이가 0.1초라는 뜻이 아니다. 개별 길이가 d라면 전체 구간은 d + (요소 수 - 1) × 간격이다.

등장 순서는 화면의 읽는 순서나 사용자가 지정한 순서에 맞춘다. 마지막 요소가 등장하고 멈출 시간까지 전체 영상에 포함되는지 확인한다.

### 모션 블러

이동 방향과 속도에 맞는 잔상을 빠른 구간에만 적용한다. 가로 휩 팬에는 가로 방향 블러를 적용하고 전환 종료 후에는 없앤다. 일반적인 균일 블러는 모든 방향을 흐리게 하므로 방향성 모션 블러와 동일하다고 설명하지 않는다.

프로젝트에서 지원하면 시간 샘플링 또는 방향성 블러를 사용한다. 지원이 없으면 근사 방법과 한계를 밝힌다. 움직이지 않는 자막과 로고에 불필요한 잔상을 넣지 않는다. 종료 프레임에서 잔상이 남거나 요소가 겹쳐 보이지 않는지 확인한다.

## 시간·프레임 처리

- 프레임 수 = 지속시간(초) × 프로젝트 fps.
- 지속시간(초) = 프레임 수 ÷ 프로젝트 fps.
- 실제 코드에 정수 프레임이 필요하면 프로젝트 관례에 따라 반올림하고 적용한 값을 기록한다.
- 4프레임은 30fps에서 약 0.133초, 60fps에서 약 0.067초다. '4프레임'과 '0.13초'를 모든 fps에서 같은 것으로 처리하지 않는다.
- 초 단위 요청이면 실제 프로젝트 fps로 환산한다. 프레임 단위 요청이면 지정 프레임 수를 우선한다.
- 일정한 이동이 필요한 팬·트랙과 순간적인 속도가 필요한 휩 팬·스냅 줌의 속도 곡선을 구분한다.
- 영상 렌더링은 재생 시각 또는 프레임에 따라 계산해 동일한 시점에 동일한 결과가 나오게 한다. 프로젝트 렌더 방식에 맞지 않는 임의의 타이머를 사용하지 않는다.

## 요청을 받았을 때 작업 순서

1. 프로젝트 파일, 사용 기술, 화면 크기, fps, 전체 길이, 보유 이미지와 모델을 확인한다.
2. 요청을 효과명·대상·방향·시작·지속시간·이동량·종료 상태로 정리한다.
3. 카메라 효과인지 개별 오브젝트 애니메이션인지 구분한다. 자막과 로고를 화면에 고정해야 하는지도 확인한다.
4. 자료로 구현 가능한 범위를 판단한다. 단순한 수치는 기존 스타일에 맞춰 정하고, 결과를 크게 바꾸는 모호함만 질문한다.
5. 장면 레이어 또는 3D 카메라에 효과를 구현한다. 원본 자산은 보존한다.
6. 시작·중간·종료 화면과 전환 앞뒤를 확인한다. 가능하면 미리보기를 재생하거나 렌더한다.
7. 적용한 효과, 시간, 주요 설정, 확인 결과, 남은 제한을 짧게 보고한다.

- 팬과 트랙, 틸트와 페데스탈, 달리와 줌을 혼동하지 않았는가?
- '카메라 이동 방향'과 '장면이 화면에서 흐르는 방향'을 구분했는가?
- 이동이나 회전으로 화면 가장자리에 빈 공간이 생기지 않는가?
- 전환이 끝난 뒤 글자와 제품이 선명한가?
- 줌의 기준점이 의도한 대상에 있는가?
- 깊이 효과를 요청받았다면 레이어별 움직임이 다르게 나타나는가?
- 로고와 제품 라벨이 변형되거나 가려지지 않았는가?
- 실제 fps에 맞는 길이로 구현했는가?
- 정지 이미지로 만들 수 없는 제품 측면을 임의로 만들지 않았는가?
- 구현하거나 확인하지 않은 내용을 완료로 보고하지 않았는가?
- 펀치 인에 중간 확대 프레임을 넣지 않았는가?
- 달리 줌에서 주 대상의 화면 크기가 유지되는가?
- 스피드 램핑 구간 사이에 위치나 소스 재생 시점이 튀지 않는가?
- 랙 포커스가 끝난 뒤 의도한 대상이 선명한가?
- 이즈 아웃은 도착하면서 감속하고, 오버슈트는 목표값으로 정착하는가?
- 안티시페이션이 본 동작 전에 배치되고, 제품·로고를 불필요하게 변형하지 않는가?
- 스태거의 시작 간격과 개별 동작 길이를 구분했는가? 마지막 요소까지 종료되는가?
- 모션 블러는 요청한 방향·시간에만 나타나고 종료 후 사라지는가?
