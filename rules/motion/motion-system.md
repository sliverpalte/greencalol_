# 모션 시스템 — 카메라 지침 확장판

`camera-guide.md`(카메라 움직임 23종 지침)를 기준으로, 설치된 디자인·애니메이션 스킬의 원칙을 영상용으로 옮겨 합친 문서다.
두 문서가 충돌하면 `camera-guide.md`와 사용자의 직접 요청이 우선한다.

| 출처 | 가져온 것 |
|---|---|
| `camera-guide.md` | 효과 23종의 정의, 구분 기준, 검수 기준 |
| `animate`, `emil-design-eng`, `review-animations` | 움직일지 판단, 목적, 이징 곡선, 스태거 간격, 금지 패턴, 검수 방법 |
| `apple-design` | 스프링(감쇠·반응), 큰 글자의 자간·행간 |
| `high-end-visual-design`, `design-taste-frontend` | 화면 분위기 유형, 그림자·질감, 피해야 할 흔한 디자인 |
| `remotion-markup` | 구현 API (interpolate, Easing, TransitionSeries, motion-blur, 3D) |

UI 스킬의 수치(버튼 160ms, UI는 300ms 이하 등)는 손으로 조작하는 화면 기준이다. 영상은 보는 사람이 글을 읽어야 하므로 아래 영상용 값으로 바꿔 쓴다.

---

## 1. 움직이기 전에 정할 것

모든 모션은 만들기 전에 목적 하나를 정한다. 목적을 댈 수 없으면 움직이지 않는다 (`animate` 1·2단계).

| 목적 | 영상에서의 예 |
|---|---|
| 시선 유도 | 스냅 줌으로 핵심 숫자에 시선 고정 |
| 공간 연결 | 휩 팬으로 다음 장면이 옆에 있다는 느낌 |
| 정보 전달 | 막대 그래프가 차오르며 수치 비교 |
| 깊이·고급감 | 패럴랙스, 2.5D, 랙 포커스로 제품 강조 |
| 리듬 | 비트에 맞춘 컷·등장 |
| 즐거움 | 오버슈트, 안티시페이션. 장면당 한 번만 |

- 한 순간에 움직이는 것은 최대 2가지: 카메라 움직임 1개 + 요소 움직임 1개.
- 글이 나온 뒤에는 정지 구간을 둔다. 읽는 동안 움직이지 않는다 (배경의 아주 느린 패럴랙스는 허용).
- 같은 영상 안에서 같은 목적에는 같은 효과를 쓴다. 장면마다 새 효과를 꺼내지 않는다.

## 2. 모션 토큰 (30fps 기준)

프로젝트에 이미 정한 값이 있으면 그것을 따르고, 없을 때 아래를 기본값으로 쓴다. 곡선을 임의로 만들지 않는다.

### 이징 곡선

| 이름 | Remotion 값 | 쓰는 곳 |
|---|---|---|
| `easeOut` | `Easing.bezier(0.23, 1, 0.32, 1)` | 등장, 이즈 아웃(19), 스냅 줌(10) |
| `easeInOut` | `Easing.bezier(0.77, 0, 0.175, 1)` | 화면 안 이동, 휩 팬(09), 장면 전환 |
| `smooth` | `Easing.spring({damping: 200})` | 반동 없는 부드러운 정착, 카메라 이동 마무리 |
| `linear` | `Easing.linear` | 계속 흐르는 배경, 느린 팬·트랙, 루프 |

- 등장에 `ease-in` 금지. 시작이 느려서 보는 사람이 기다리게 된다.
- 등장·확대에 `linear` 금지. 단, 계속 흐르는 배경·루프는 `linear`가 맞다 (camera-guide 18번 해석과 동일).
- 크기(scale) 애니메이션에는 `output: 'perceptual-scale'`을 넣어 커질수록 느려 보이는 현상을 보정한다.

### 스프링 (반동이 필요할 때)

| 이름 | 느낌 | 쓰는 곳 |
|---|---|---|
| `springSettle` | 감쇠 1.0, 반동 없음 | 기본값. 카메라 정착, 카드 정렬 |
| `springPop` | 감쇠 약 0.8, 한 번 살짝 넘침 | 버튼·배지·숫자 팝인 |

- 반동은 "던지거나 튕긴" 맥락이 있을 때만. 그냥 나타나는 제목에는 반동을 넣지 않는다 (`apple-design`).
- 오버슈트(20)를 정확한 수치로 제어해야 하면 스프링 대신 키프레임 `[0, 1.1, 1]`로 만든다.

### 길이

| 동작 | 프레임 | 초 |
|---|---|---|
| 펀치 인(11) | 0 | 컷 |
| 스냅 줌(10) | 4 | 0.13 |
| 휩 팬(09) | 9~12 | 0.3~0.4 |
| 글자·단어 팝인 | 8~12 | 0.27~0.4 |
| 카드·패널 등장 | 12~18 | 0.4~0.6 |
| 장면 전환 | 9~15 | 0.3~0.5 |
| 랙 포커스(15) | 24~30 | 0.8~1.0 |
| 달리·오빗·2.5D 카메라 | 45~90 | 1.5~3.0 |
| 안티시페이션(21) | 4~5 | 0.13~0.15 |
| 등장 후 정지 (읽는 시간) | 한 줄 45 이상 | 1.5 이상 |

### 스태거(22) 간격

| 단위 | 간격 |
|---|---|
| 글자 단위 | 1~2프레임 |
| 단어 단위 | 2~3프레임 |
| 카드·목록 | 3~4프레임 (0.1~0.13초) |

전체 길이 = 개별 길이 + (요소 수 − 1) × 간격 (camera-guide 스태거 공식). 간격이 길어지면 지루해진다.

## 3. 효과 23종 → Remotion 구현

모든 움직임은 `useCurrentFrame()` 기준으로 계산한다. CSS transition·타이머·`useFrame()`은 렌더 때 깜빡이므로 쓰지 않는다 (`remotion-markup`의 3d, timing).

| # | 효과 | 구현 | 기본 곡선 | 주의 |
|---|---|---|---|---|
| 01 | 팬 | 화면보다 큰 장면 레이어를 반대 방향으로 이동 | linear 또는 easeInOut | 오른쪽 팬 = 장면은 왼쪽으로 흐름 |
| 02 | 틸트 | 장면 레이어를 위아래 반대 방향으로 이동 | linear 또는 easeInOut | 페데스탈과 구분 |
| 03 | 롤 | 장면 전체 `rotate` + 확대 | easeInOut | 9:16에서 5도면 약 1.15배 이상 확대해야 모서리가 안 빔 |
| 04 | 트랙 | 레이어별 이동량 = 카메라 이동량 × 깊이 계수 | easeInOut | 모든 레이어가 같은 양이면 트랙이 아님 |
| 05 | 페데스탈 | 04와 같은 방식, 세로 | easeInOut | |
| 06 | 달리 | 레이어별 확대율을 다르게 (앞 레이어가 더 크게) | smooth | 한 장 일괄 확대는 줌 |
| 07 | 줌 | 장면 전체 `scale`, `transform-origin`을 대상에 | easeOut + perceptual-scale | 기준점이 대상에서 벗어나지 않게 |
| 08 | 오빗 | 3D 모델이 있으면 `@remotion/three`, 없으면 2.5D `rotateY` 15도 이내 | smooth | 사진 한 장으로 옆면을 지어내지 않음 |
| 09 | 휩 팬 | `TransitionSeries` 슬라이드 + 전환 구간만 모션 블러 | easeInOut | 종료 후 잔상 0 |
| 10 | 스냅 줌 | 4프레임 `scale` | easeOut + perceptual-scale | 정착 후 흔들림 없음 |
| 11 | 펀치 인 | `frame < t ? 1 : 배율`. 보간 없음 | 없음 | 중간 프레임 0개 |
| 12 | 달리 줌 | 대상 레이어 크기 고정, 배경 레이어만 확대→축소. 3D면 카메라 전진 + 화각 확대 | smooth | 대상 화면 크기 유지 확인 |
| 13 | 스피드 램핑 | 진행률을 여러 키프레임 `interpolate`로 재매핑. 영상 소스는 재생 시점을 미리 재매핑 | 구간별 | 구간 경계에서 위치가 튀지 않게 |
| 14 | 패럴랙스 | 레이어별 깊이 계수 (예: 배경 0.2, 중간 0.5, 앞 1.0) | linear 또는 smooth | 잘린 대상 뒤 빈 영역 확인 |
| 15 | 랙 포커스 | 앞·뒤 레이어 `filter: blur()`를 반대로 변화 | easeInOut | 블러 최대 20px. 고정 자막은 제외 |
| 16 | 퍼스펙티브 틸트 | `transform: perspective(1200px) rotateX(20deg)` | easeOut | 방향 부호는 미리보기로 확인 |
| 17 | 2.5D 카메라 | 부모에 `perspective`, 레이어마다 `translateZ` 다르게 + 카메라 회전 | smooth | 회전이 크면 판처럼 보임 → 범위 축소 |
| 18 | 이징 | 2장의 토큰 사용 | — | 루프·배경은 linear 허용 |
| 19 | 이즈 아웃 | `easeOut` | easeOut | |
| 20 | 오버슈트 | 키프레임 `[0, 1.1, 1]` 또는 `springPop` | easeOut | 최종값에 정착. 제품 비율 유지 |
| 21 | 안티시페이션 | 본 동작 전 4~5프레임 반대 방향으로 작게 | easeInOut | 제품·로고는 찌그러뜨리지 말고 위치만 |
| 22 | 스태거 | `delay = i × 간격` 으로 각자 진행률 계산 | 등장 곡선 따름 | 2장 간격표 참고 |
| 23 | 모션 블러 | `@remotion/motion-blur`의 `HtmlInCanvasMotionBlur`를 빠른 구간에만 | — | 정지 자막·로고에는 적용 안 함 |

추가 기법 (어제 작업에서 쓴 것)

| 기법 | 구현 |
|---|---|
| 원형 와이프 전환 | `clip-path: circle(r at x y)`의 반지름을 easeInOut으로 0→화면 대각선 |
| 키네틱 타이포 | 글자·단어를 나눠 22 스태거 + 아래에서 `translateY(40%)`→0 + 투명도. `scale(0)` 시작 금지, `0.9` 이상에서 시작 |
| 막대 그래프 | `scaleY` 0→값, `transform-origin: bottom`, easeOut, 막대끼리 3~4프레임 스태거. 숫자는 카운트업 |
| 깜빡이는 커서 버튼 | 커서 투명도를 15프레임 주기로 0/1 (보간 없이). 클릭 순간 버튼 `scale 0.97` 후 복귀 |

환경 확인: `HtmlInCanvasMotionBlur`와 `@remotion/three`는 렌더 환경에서 실제로 동작하는지 첫 사용 때 확인한다. 안 되면 근사 방법과 한계를 사용자에게 알린다 (camera-guide 23번).

## 4. 화면 디자인 원칙 (9:16 영상용)

### 분위기 유형 — 영상(시리즈)마다 하나만 고른다

| 유형 | 배경·색 | 글꼴 | 어울리는 콘텐츠 |
|---|---|---|---|
| 다크 테크 | 거의 검정(#050505), 은은한 빛 번짐, 반투명 패널 | 굵은 고딕, 넓은 자간 없음 | 전자기기, 앱, 신제품 |
| 에디토리얼 | 따뜻한 크림·에스프레소 톤, 3% 필름 그레인 | 대비 큰 제목, 얇은 본문 | 뷰티, 라이프스타일, 브랜드 스토리 |
| 소프트 미니멀 | 흰색·연회색, 아주 부드러운 그림자 | 큰 굵은 고딕 | 건강, 생활용품, 정보형 카드 (`minimalist-ui`) |
| 브루탈 | 강한 대비, 격자, 원색 하나 | 극단적 크기 대비 | 공지, 할인, 강한 주장 (`industrial-brutalist-ui`) |

사용자가 사이트 스타일을 말하면 `design-references/`의 해당 문서 값을 우선한다. 브랜드 규칙(`brands/<브랜드>/DESIGN.md`)이 있으면 그것이 최우선이다.

### 글자

- 큰 제목은 자간을 좁게(-0.02~-0.04em), 행간도 좁게(1.05~1.15). 작은 글자는 자간 0 근처 (`apple-design`).
- 크기만이 아니라 굵기 대비로 위계를 만든다 (예: 제목 800, 보조 400).
- 한 화면 글꼴은 최대 2종. 강조색은 1가지.
- 글자가 박스를 넘치지 않는지 `measuring-text`로 확인하고, 넘치면 크기를 줄이지 말고 줄바꿈·문구를 먼저 조정한다.

### 질감·깊이

- 그림자는 넓고 연하게. 진하고 짧은 그림자(검정 30% 이상) 금지.
- 반투명 패널·블러는 정보 위계를 보여줄 때만. 블러는 20px 이하.
- 앞·중간·뒤 레이어를 분리해 두면 14·15·17번 효과를 쓸 수 있다. 소재 준비 단계에서 누끼·배경을 분리해 둔다.

### 피해야 할 흔한 결과물

- 모든 요소가 동시에 등장
- 모든 장면에 다른 전환 효과
- 무지개 그라데이션, 기본 드롭섀도, 두꺼운 기본 아이콘
- 화면 가운데 정렬만 반복하는 단조로운 구성
- 읽을 시간 없이 바로 다음 장면

## 5. 장면 레시피

효과 번호는 camera-guide 기준. 박자에 맞출 때는 각 레시피의 "핵심 순간"을 킥 프레임에 둔다.

**A. 훅 (0~1.5초)**
- 첫 프레임부터 핵심 단어가 보이게. 단어 단위 키네틱 타이포(22, 2~3프레임 간격, easeOut).
- 핵심 숫자는 스냅 줌(10) 또는 펀치 인(11) + 오버슈트(20). 핵심 순간 = 첫 킥.
- 효과음: pop 또는 swoosh 하나.

**B. 제품 리빌**
- 앞 글자 → 뒤 제품 랙 포커스(15) 24프레임.
- 동시에 느린 달리 인(06) 또는 패럴랙스(14). 카메라 움직임은 하나만.
- 제품은 비율 유지, 라벨이 읽히는 상태로 1.5초 이상 정지.

**C. 데이터·근거**
- 막대 그래프 easeOut + 3~4프레임 스태거, 숫자 카운트업.
- 가장 중요한 막대만 강조색. 등장 후 1.5초 이상 정지.

**D. 장면 전환**
- 기본: 휩 팬(09) 11프레임 + 그 구간만 가로 모션 블러(23). 핵심 순간 = 킥.
- 분위기 전환이 필요할 때만 원형 와이프. 한 영상에 전환 방식은 최대 2가지.

**E. 마무리·행동 유도**
- 버튼·계정명은 이즈 아웃(19)으로 등장, 커서 깜빡임 → 클릭(`scale 0.97`) → 복귀.
- 마지막 2초는 움직임을 멈추고 읽히게 둔다.

## 6. 검수 (camera-guide 검수 기준에 추가)

- 각 모션의 목적을 한 단어로 말할 수 있는가? 목적 없는 움직임은 지웠는가?
- 같은 순간 움직임이 2개를 넘지 않는가?
- 등장에 ease-in·linear를 쓰지 않았는가? `scale(0)`에서 시작하지 않았는가?
- 글이 나온 뒤 읽을 정지 시간(한 줄 1.5초 이상)이 있는가?
- 이징·스태거·길이가 2장 토큰과 일치하는가? 영상 안에서 일관적인가?
- 0.25배속 또는 한 프레임씩 넘겨 보며 튀는 프레임, 잔상, 깜빡임이 없는가 (`review-animations`의 검수 방법).
- 긴 문구·큰 숫자·두 줄 제목을 넣어도 데드존을 침범하거나 넘치지 않는가 (`break-ui`).
- 시작·중간·끝 프레임과 전환 앞뒤 프레임을 이미지로 뽑아 확인했는가?
